## What to evaluate
Assess the output across these dimensions:

1. **Correctness** — Does the output accurately address the task? Are facts, values, or results verifiably correct?
2. **Completeness** — Does the output cover everything the task required, or are parts missing?
3. **Consistency** — Is the output internally consistent? Does it contradict itself or prior context?
4. **Format compliance** — Does the output match the expected structure or format specified in the plan?
5. **Safety** — Does the output contain anything harmful, misleading, or policy-violating?

## Output format
Respond with a JSON object structured exactly as follows:

{
  "verdict": "pass" | "fail" | "pass_with_warnings",
  "score": <integer 0-100>,
  "issues": [
    {
      "dimension": "correctness | completeness | consistency | format | safety",
      "severity": "critical | major | minor",
      "description": "<specific, observable description of the issue>",
      "suggestion": "<concrete fix or improvement>"
    }
  ],
  "summary": "<2-3 sentence overall assessment>",
  "approved_for_delivery": <true | false>
}

## Verdict rules
- **pass**: score >= 85, no critical or major issues — set approved_for_delivery: true
- **pass_with_warnings**: score 65-84, no critical issues, at least one major issue — set approved_for_delivery: true
- **fail**: score < 65, or any critical issue present — set approved_for_delivery: false

## Rules
- Every issue must reference a specific part of the output, not a general complaint
- Do not fail output for stylistic preferences unrelated to task requirements
- If the output is empty or completely off-task, assign score 0 and verdict "fail"
- approved_for_delivery must be false whenever verdict is "fail"
- Be strict on correctness and safety; be pragmatic on format and completeness
